# 通用扩展器续批二：能源转发

接续 `UNIVERSAL_EXTENDER_CONTROL_2026-09-13.md`。原版通用扩展器使用 `EXTENDER_ALL` 与 delegate 机制；移植版网络以 `IEnergyBlock` 和 Forge capability 为入口，因此增加独立的 `EnergyRelayBlockEntity` 适配层。

## 完成

- 通用扩展器/通用桥接器转发原生 GT 能源：能源类型、输入输出面、包大小（含负 KU）、数量、模拟/执行标志全部传给实际机器；没有中间储能和能源兑换。
- 能源类型、额定/最小/最大包、需求、可提取量、储能/容量查询均沿同一方向路由。目标仍决定是否接收、是否允许提取以及过载行为。
- Forge Energy 使用单独的实时能力转发，尊重目标的接收/提取限制；拆除和 capability 失效后旧包装也不能继续操作。
- 普通物品/流体扩展器不能转发能源。循环连接返回不可用，不吞能、不产生能量，不强制加载区块。
- 修正普通机器能源需求查询的零除和负包数量问题。

## 验证

`batch-relay-energy-tests.log`：135 项 required GameTest 全部通过，无 ERROR，进程退出码 0。新增 4 项集成测试覆盖六种原生能源×六面×两种方块、负包/模拟、实际 ZPM 经桥接器供电的能量守恒、Flux 引擎能力与朝向、循环和拆除。未构建 JAR。

runClient：ZPM 放电器→通用桥接器→匹配电压机器；Flux 能源线→桥接器→Flux 引擎背面；用扳手改扩展器两面后重测；移除目标检查是否停止输送。输出仅主动推送的 ZPM/活塞引擎，不会因桥接而额外开放拉取。

这里实现的是 GT 能源接口与 FE 接口，不代表所有第三方 capability、原版物流线/覆盖板、USB/HDD 已完成。红石与比较器的原生 API 限制见上一批说明。
