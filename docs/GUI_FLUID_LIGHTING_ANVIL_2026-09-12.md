# 流体 GUI 同步、预览光照及砧交互续批

## GUI 流体数量不更新

普通机器菜单（包括蒸馏塔）有两处阻断：Minecraft 传入的是玩家的 `ContainerListener` 对象，旧代码尝试把它当 `ServerPlayer`，接收者列表一直为空；客户端收到服务端包后又调用 `getSender()`，该方向没有服务端玩家发送者，因此仍无法找到菜单。

现在使用构造菜单时的实际玩家，仅对其当前打开的菜单发送变化；客户端从本地玩家获取当前菜单。包内携带 containerId，旧窗口的迟到包不能写进另一个窗口，并限制为服务端到客户端方向。流体种类、数量、NBT 和清空状态均参与同步，槽与包保留独立副本，避免可变 FluidStack 让差异比较失效。

网络协议由 1 更新为 2；联机时服务器和客户端都需使用本次版本。

## 三维预览光照

原预览调用 `PoseStack.scale(scale,-scale,scale)`。Minecraft 1.20.1 在非均匀缩放时用 `fastInvCubeRoot` 归一化法线，负行列式超出该近似的适用范围。直接调用原实现的回归得到约 `-2.101E25` 的上方向法线，足以造成错误的明暗。

新增 `PreviewTransforms`，模型矩阵保持原来的 GUI 映射，法线单独作 Y 镜像，均匀尺寸不参与单位法线缩放。保留相机旋转、物品灯光、满亮光照贴图及渲染结束后的状态恢复。没有更换材质或把渲染改成无条件纯白。

## 继续移植：砧

依据原版 `MultiTileEntityAnvil.onBlockActivated3` 补入：

- 顶面放入/取出工件，侧面点击时将唯一一堆工件均分到两个槽。
- 奇数数量先返还一件，剩余平均分配；两个槽已有工件时不再均分。物品 NBT 保留。
- 空砧顶面可以放置硬锤，再点顶面取回。沿用工件同步、渲染、NBT 与破坏掉落机制。
- 工件存在时持锤继续加工；不会把这次存锤/分堆当作砧维修、附魔系统全部完成。

## 验收

1. 打开蒸馏塔 GUI，保持窗口开启，通过管道输入/抽出流体或让配方继续工作。数量应实时变化，抽空后图标消失；普通流体机器同测。
2. 快速关闭并打开另一台机器，不能出现前一台机器的流体。
3. JEI 预览检查四周旋转、滚轮缩放、分层，方块不应突然过亮/过暗；材质染色应保留。
4. 砧顶面放五件可加工材料，空手点侧面，应变成两堆各二件并返还一件；两堆都在时再次点侧面应不变。
5. 清空砧，顶面放锤、退出重进后取回；另测破坏砧时锤只掉落一次。

## 验证边界

法线回归在旧实现下失败、修复后通过；独立注册/模型/工具/容器契约通过。新增服务端测试覆盖菜单持续广播、包编码解码与应用、数量/NBT 变化、清空、旧窗口拒绝和停止发送，以及砧分堆与存锤。最终 60 项 GameTest 全部通过；`runGameTestServer build -x processResources --offline --console=plain` 构建成功（2m 31s）。本批没有修改资源，沿用已处理资源。

尚未做真实客户端 GPU 或联机交互验收；服务端测试不能证明全部视觉效果。整体移植蓝图仍未完成，核反应堆、物流核心及生态等缺口继续保留。
