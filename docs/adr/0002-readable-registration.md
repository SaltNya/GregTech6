# 0002：可读注册入口与历史导入隔离

状态：已采用，2026-09-11。

## 问题

旧 GT6 符号表同时承担工厂、静态材料定义与引用，新增内容依赖难辨认的简称和位置参数。只移动文件不能解决初始化依赖、名字隐含行为，以及重新生成覆盖手写逻辑的问题。

## 决定

1. 将材料工厂、导入目录、引用目录、启动关联阶段分开。导入材料按元素、化合物、矿物、石材、木材分组，并使用材料规范名称作为 Java 字段名。
2. 手写内容使用完整数据类名及具名 builder。基础机器定义显式携带配方表和并行度，运行实例消费定义。
3. 新材料/流体入口严格检查重复身份、参数和注册阶段。历史导入路径保留原始语义，迁移历史冲突另行处理，避免本轮顺带改变材料映射。
4. 旧简称多数保留为弃用兼容层；旧枚举和 MT 特殊字段单独保留。兼容层不是推荐扩展点。
5. 维护重新生成工具与回归测试；历史数据骨架只输出到隔离目录。

GTM 仅提供分离定义、注册、运行状态的设计参考。本轮实现独立编写，没有复制 GTM 源码，没有导入 GT5 材料或机器规则。

## 后果

新增定义更易读，错误更早暴露；兼容层让迁移可以逐步完成。代价是过渡期仍存在旧入口及部分全局可变对象，系统尚未成为完全冻结的注册表或通用插件平台。通用多方块结构规则、能源运行语义和配方执行器的正确性不由本决定解决。

使用方式和验证命令见 `../REGISTRATION_GUIDE.md`。
