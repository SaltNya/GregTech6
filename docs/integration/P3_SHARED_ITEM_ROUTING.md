# P3 — Shared weighted item routing and actual transfer accounting

This wave replaces the saltnya first-exit BFS in both platform entities while preserving its 126 IDs, materials, buffers, covers, component/NBT keys and general hop-by-hop lifecycle. It uses code from all three projects to select the new implementation; source hashes and author/license evidence are retained in `core/provenance/shared-item-routing-source-integration.json`. The original source directories and available history are unchanged.

## Adopted implementation

- `WeightedItemPipeRoutes` implements brokestar's iterative minimum-step relaxation with stable insertion-order ties. Positive material/restrictor weights are accumulated exactly; long addition saturates instead of wrapping. A 32768-visited bound and loaded-chunk boundary follow masson's discovery policy. Both platform adapters use this one frontier, including reciprocal connected faces, side masks, ingress history and outgoing/incoming covers. The unused baseline FIFO scan is removed.
- Exit discovery now asks whether the actual destination face can accept the offered component-bearing stack. A present but full/filtered handler is not an exit. Platform API differences stay in the capability adapter. The origin is excluded from the frontier and direct delivery respects actual connected faces.
- `ItemPipeTransfer` and `ItemTransferAmounts` use masson's validated remainder/partial-commit accounting. They simulate, refresh the actual capability, then retain only confirmed delivery counts, including validated earlier slots if a later slot throws. A vanished capability consumes nothing. Baseline merge-before-empty slot order is retained. Both entity callers now shrink source by actual acceptance instead of splitting the simulated quantity before execution. Pipe-to-pipe delivery uses the receiving face's capability, so an incoming cover is not bypassed. Side views also enforce disabled input/output masks.
- Platform adapters carry Minecraft stack identity/components or old NBT, native/Forge handler lookup and one diagnostic per weakly held failing handler. No second material registry, transport registry or masson topology/storage runtime is introduced.

The full masson cached route/topology reservation mechanism is not claimed adopted: this integration recomputes loaded routes each transfer cycle and refreshes the destination between simulation and execution. Handlers that mutate a destination and then lie or throw before reporting a valid remainder cannot provide authoritative delivery counts; only confirmed slots are consumed. The bounded discovery limit and unvisited networks need scale validation. Forge runtime parity and all source routing/cover semantics remain subject to broader validation.

## Shared resources and native client boundary

All remaining 2927 baseline PNG files and their 123 animation metadata files were moved byte-for-byte from the integration's Forge resource root to shared core, after original/target equality checks. The original snapshot remains intact. This completes the remaining PNG migration in one wave; future code-only integrations can reuse resource task outputs. Manifest: `core/provenance/remaining-shared-textures-source-integration.json`.

Resource inspection found 144 older native model files still using `forge:composite`. Their geometry-loader namespace is adapted to `neoforge:composite`; child layers, geometry and textures are unchanged. The additive adaptation manifest records original/previous/current hashes rather than rewriting historical source records: `core/provenance/native-composite-model-loader-adaptation.json`. An actual native client attempt then exposed 1226 more Forge-loader JSON files in shared core and a camel-case `plateTiny` texture alias. Loader-dependent JSON now lives in the corresponding platform resource roots: Forge retains exact baseline bytes; Neo uses `neoforge:composite`. Generic models and all PNG bytes remain shared. `MaterialPrefix.getTextureFileName()` lowercases explicit aliases using Locale.ROOT without changing registry identities. Manifest: `core/provenance/native-client-resource-boundary.json`. The recipe-loader duplicate-initialization guard remains intact; its deferred-retry exception is recorded as secondary to the original resource failure.
