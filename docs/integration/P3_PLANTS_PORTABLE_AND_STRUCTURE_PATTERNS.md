# P3 — Plants, portable manufacturing and shared multiblock patterns

The original icon order/classification now lives in core, with all 17 indicator flowers, 16 glowtus lilies and 18 large/small icon saplings registered in Neo through their real bush/desert-flower/lily factories. The nine tree species already have separately registered growable wood saplings. The original icon saplings are bushes; this wave does not mislabel them as another growable-tree system. Source flower metadata, explicit desert sand gate, self drops, lily placement and glow level 15 are retained. Native removes the obsolete Forge PlantType entry point while keeping the vanilla placement predicate; real placement remains unverified. All 18 staged optional sapling tag references are now required registered IDs.

Twenty-two actual source fluid attachments (18 material variants plus tap/nozzle/funnel/cap aliases) use the original phase/acid gates, hand interaction, down-pouring and tool-facing rules over existing native fluid handlers. Five plain original raw ceramic form items are connected. Source stack-size/material/properties are retained; no infinite fluid-display ingredient is introduced. Native uses fluid-stack copies to preserve components.

Thirty-eight original portable crafting/smelting/reclaim recipe files are moved byte-for-byte to core. Forge loads these original recipes directly; Neo's reloadable built-in pack adapts only the singular recipe directory and result codec. Both platforms have one editable source recipe stream. Original aliases and namespace identities are retained. Remaining station/plant/attachment systems are tracked separately.

The original full large-machine, fusion, matter-fabricator, boiler and turbine structure data and named material/part definitions are extracted into core. Primitive offsets, six-axis port roles, lowest-layer emission and loaded-only hollow-tank validation are shared. Forge keeps its original public Cell/Role and registry APIs through thin conversions and invokes the shared tables. Source coordinates, part numeric IDs and role meanings are preserved. This is preparation for the native multiblock-controller wave, not a claim that Neo already runs fusion or every large machine.

Comparison sources: brokestar's bound-pattern checker centralizes rigid structure judgments and forming/binding; masson's StructureAccess scanner separates world reads, diagnostics and palette checks. Those alternate registries/binding algorithms are not imported. This wave separates immutable source geometry from world/registry access and retains baseline no-mutation/loaded-before-read validation. The native controllers still need the full capability/ownership/lifecycle integration; comparison does not establish their runtime superiority.

Original model/blockstate/geometry and source recipe bytes, source hashes, authors and comparison hashes are recorded in `core/provenance/plants-portable-multiblock-patterns-integration.json`. All original notices/licenses/history remain preserved; no publication or relicensing is performed.

Necessary core/Neo/Forge compilation passed in 26 seconds after fixing the pure-core annotation dependency and native WaterlilyBlock codec generic. One existing ordinary Neo short startup passed in 4m53s including resources, registered 51 plants, loaded 38 portable recipes and 44 finite bottle recipes (6325 total crafting), and observed 200 ticks followed by normal save/stop. This also covers the preceding empty-bottle fallback pack change. A Mojang public-key request timeout was nonblocking and did not prompt any retry/extra startup. Receipts: `verification/p3-plants-portable-structures-compile.json` and `verification/p3-neoforge-plants-portable-structures-startup.json`; no subsystem fixture was added. Actual plant spawning/placement/cutting/processing, client rendering/tints, attachment transfer conservation, actual grid crafting, controller ownership, independent world reload, old saves and fresh jars remain incomplete or unverified. Indicator-flower crafting/processing/tooltips/potted variants and further natural generation stay on the next dependency batches.
