# Issue 18: original component covers

Compact electric pumps, conveyors and robot arms now attach and run as covers. Normal hosts default to output; pipes force input. Pump/conveyor direction uses a screwdriver. Robot arms use a monkey wrench for direction and a screwdriver (sneak to decrement) for the signed-short source/target slot. Magnifiers inspect slots, crowbars return the actual cover, and cover tool actions are consumed before host rotation. Compact sensors remain components.

The shared rules implement original throughput, cadence, one-group movement and pipe restrictions. Native adapters handle capabilities and storage, including live cached face gates, controller pause/resume, client packets, source direction textures and pipe receive masks. Existing machine/pipe/tank/chest/battery/USB hosts keep their native slots. Other ticking GT block entities receive lazy cover slots through the native block-entity boundary. Placement checks each face's actual fluid/item handler; vanilla hosts and unticking GT entities reject components.

Fallback covers persist with full block-entity saves and synchronize separately from native inventory/menu packets. Native partial updates cannot erase them. Cover NBT is removed from fallback block-item copies, since actual block replacement drops the covers separately. Chunk unloading only clears tracking and never queries or reloads a world chunk; loaded/revived hosts are tracked again. Tick dispatch checks the entity's identity in the already loaded chunk.

Finite actual-world fixtures check six existing host families plus 26 representative fallback entity classes (242 accepted faces), two-way pump conservation, one-group conveyor movement, both robot slot directions, live cached gates, controller pause/removal, tool interactions, save/load, one-cover break drops, unload preservation and actual client sync. Both platforms passed all nine fallback lifecycle checks, displayed the original robot-arm face in the actual world, saved their dimensions and exited normally. NeoForge reported zero generation holders waiting before shutdown. Final receipts are recorded in the aggregate verification record. These checks do not establish a saved-world restart, old-user-world compatibility, a complete survival chain, dedicated-server behavior or arbitrary external handlers.

Initial generic host validation exposed a Mixin interface-super invocation issue, an overlarge second texture reload in the smoke harness, and a world lookup risk during chunk unloading. NeoForge also retained unfinished generation holders when the harness exited immediately after teleporting; the isolated harness now waits for both active and pending-unload holders to be ready before shutdown. These were repaired before final packaging; the final run must exit normally, not merely emit a success receipt.
